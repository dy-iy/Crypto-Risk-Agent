# 资产管理收敛为关注币种与风险日报

2026-09-09。根据确认的方案实施，保留完整币种库、账号关注与个性化日报；游客使用本地自选，主动选择后才导入账号。

## 已修复与调整

- 删除独立资产雷达组件、桌面与手机资产入口、持仓表单及重复资产管理。首页引导改到看盘；“我的关注”集中提供搜索、添加、取消关注、阈值设置和风险信息入口。
- 看盘星标与账号关注使用同一个状态和数据源；图表设置仍在本地。未接入行情的币种可以关注并进入日报，明确显示“暂不支持行情”。币种详情也可以关注，未收录风险数据时显示空状态。
- `/portfolio?asset=BTC` 转至 `/market?symbol=BTCUSDT`；不支持行情的币种及无效参数转至 `/my?tab=assets`。同步适配新闻和币种详情的历史返回链接。
- 资产日报更名关注日报。新日报仅分析当前关注币种，删除敞口加权，模型输入过滤持仓、成本和仓位字段；保持新闻风险与币种关联性分析。
- 没有关注币种时，手动生成返回明确提示；定时任务跳过生成和飞书发送，不关闭已有订阅。旧日报内容保留并标注历史版本。
- 日报记录关注版本；增删关注或修改阈值后，界面提示旧日报已过期，由用户重新生成或等待下一次定时任务。
- 档案统计卡只在“总览”展示，手机打开关注管理后可以直接搜索和操作。

## 根因与实现边界

此前看盘自选来自浏览器，而日报读取后端资产库；两份名单互不相通。资产管理、档案库和日报又共享持仓计算，单纯隐藏菜单会留下失效入口和无来源的日报。

新增轻量关注服务直接读取既有 SQLite 记录，跳过行情抓取和风险快照生成。取消关注只更新 `is_watched`，重新关注保留阈值；历史持仓、成本、记录 ID 不变。写操作使用 SQLite 事务保护并发，不增加表或列。旧资产接口、历史数据导出及账号删除接口仍兼容。

浏览器验收还发现直接打开币种详情页时原先未主动核验身份，可能把已登录用户的关注保存到游客本地名单。现已在允许关注前核验登录状态。

## 接口与状态

| 接口 | 用途 |
| --- | --- |
| `GET /api/follows` | 当前账号关注快照 |
| `POST /api/follows`，`{symbol}` | 幂等添加，默认风险阈值 70 |
| `PATCH /api/follows/{symbol}`，`{alert_threshold}` | 修改 0–100 的整数阈值，支持 0 |
| `DELETE /api/follows/{symbol}` | 幂等取消关注，保留历史记录 |

成功响应统一为 `{items, revision}`；条目仅含币种代码、基础币种、名称、阈值、创建与更新时间。使用 Pydantic 响应模型，不返回持仓字段。接口要求登录，沿用 CSRF、禁止缓存响应及变更限流，不接受通过查询参数操作其他账号。

新日报兼容原响应字段，额外记录 `report_kind: "follows_v1"` 和 `follows_revision`。旧日报不做重写。

前端共享关注状态合并读取、串行保存并阻止同币种重复提交。失败保留最近有效名单；账号切换取消旧请求，旧响应不能覆盖新账号。游客名单独立保存，导入默认不勾选，失败项保留重试。关注同步具有超时、数据格式校验和重新聚焦时的刷新。

## 验证说明

后端测试在隔离副本与临时数据库执行，禁用模型访问及调度。浏览器使用实际组件和网站外壳的隔离打包页，账户及写接口由明确的测试数据处理；行情复用此前真实 API 获取的快照。浏览器结果不等同于生产 Next.js 服务端渲染或线上构建验收。

遵守项目约束，没有执行 `npm run build`、开发服务启动、部署或重启；没有执行生产历史数据清理，也未改变现有订阅开关。
