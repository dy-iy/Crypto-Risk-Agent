## 已修复

| 优先级 | 根因与实际修改 |
| --- | --- |
| P0 | 本地报告和聊天使用全局键，登录时把所有本地报告同步到当前账户。改为由后端核验的用户 ID 划分存储；退出/切换账户重置页面状态、取消旧请求，防止旧结果写入新账户。日报等私有响应不再落入通用持久缓存。 |
| P1 | 清缓存后仍在进行的旧请求会重新填入过期结果。为缓存添加失效代次和请求归属校验，保留并发请求去重。 |
| P1 | 隐私模式、存储配额耗尽会让读写操作抛错。统一存储访问，降级到当前标签页内存并明确提示；云端报告同步失败不再静默吞掉。 |
| P1 | 流式请求缺少总超时，SSE 只处理单行数据及完整 LF 分隔符。补齐超时、账户取消、UTF-8 分块、CRLF、多行数据、末尾事件、非法 JSON、空流、大事件限制与 reader 清理。 |
| P1 | `NaN`、`Infinity` 及数字字符串可进入模拟交易或资产持仓，破坏余额及 JSON。增加 API 和交易引擎两层有限数校验；Pydantic 错误保留标准 `detail` 列表，但不回显原始输入和不可序列化对象。 |
| P1 | JSON 写入共用临时文件，并发可能互相覆盖，模拟账户保存失败仍返回成功。改为唯一临时文件、完整写入后替换、拒绝非法浮点数；模拟操作保存失败回滚内存并报告失败。文件读取权限错误也不再被误当成坏 JSON 丢弃。 |
| P1 | 限流信任 X-Forwarded-For 最左侧值，当前 Nginx 追加转发地址的部署方式下可被伪造。改取边缘代理追加的地址；限制请求 ID 长度和字符，并为 API 增加禁止缓存的响应头。 |
| P1 | 请求体只相信 Content-Length 或一次性读取无长度请求。改为统计实际分块字节并在超限时停止读取，合法请求体仍完整交给后续路由。 |

## 仍未处理的条件与风险

1. **部署目标不一致**：实际 `kassa-wiki.top` 指向 Kassa Wiki（另一服务），风控路由返回 404；本项目位于 `crypto.kassa-wiki.top`。现有 Nginx 的后端目标为 8000，任务约定为 8001，且 8001 未监听。没有覆盖另一站点，需要先决定域名及切换安排。
2. **旧版本地数据归属不明**：未绑定用户的旧报告/聊天以及按用户名保存的旧助手记录保留原始浏览器存储，没有自动迁入任何账户，也没有删除。云端报告仍从原接口读取；旧本地记录需要确认所有者后迁移，避免把其他人的内容导入当前账户。
3. **密码 pepper 未配置**：当前 `.env` 未配置 `AUTH_PASSWORD_PEPPER`。已有账户的密码哈希依赖当前设置，直接新增 pepper 可能让旧密码无法登录；还需处理 dotenv 与认证模块的加载顺序，因此未擅自改变认证材料。
4. **剩余 Python 依赖告警**：FastMCP 2 的两项告警涉及 Windows 安装命令和 GitHub OAuth Proxy，本项目当前通过本地 stdio 使用 MCP，不走这些入口；修复版要求跨到 3.x，暂未扩大升级范围。DiskCache 一项告警需要攻击者能写入缓存目录，当前审计没有提供修复版本。不能把“当前未使用受影响入口”当作包本身已修复；后续启用 OAuth/网络 MCP 前应完成迁移，并保持缓存目录不可由外部用户写入。
5. **上线和真实外部链路**：未构建、重启或部署修改，也未执行真实 DeepSeek/RPC/Tenderly 分析。真实性、耗时、额度和生产 Core Web Vitals 需在部署环境补验。

## 后续建议

1. 明确域名和后端端口后，执行一次受控的生产构建、部署及登录/报告/资产/链上分析验收。
2. 对旧本地记录实施用户确认的归属迁移，并制定兼容旧密码哈希的 pepper 启用方案。
3. 将本次新增回归和依赖审计接入 CI，保留可复用的浏览器账户隔离场景；在独立分支验证 FastMCP 3 升级并处理剩余依赖告警。
4. 渐进拆分大型看板与模拟交易组件，并依据真实请求和性能测量继续减少重复行情请求。
