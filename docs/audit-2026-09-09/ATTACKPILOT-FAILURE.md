# AttackPilot 任务失败定位与修复

## 实际原因

截图任务 `f3bb65e0-4522-4d43-8b98-93e83563ea51` 于 2026-09-09 22:59:33 至 23:01:20（北京时间）运行约 107 秒后失败。
读取任务数据库与原始错误日志确认调用链为：

`DAppProcess → TxDetailAgent → TxDetailDao → TenderlyDao._load_contract_name → ContractSourceDownloader → httpx.ConnectTimeout`

这次阻断发生在合约名称查询阶段，尚未进入正常的后续智能体分析。工作流返回 `RUNTIME_ERROR`，worker 又将其替换成通用错误，导致界面仅显示“未生成有效报告”。前后端一致性审查还对缺少报告的任务计算默认低分，不能据此判断链上风险。

## 已修改

- 交易摘要只读取实际使用的交易数据，跳过无用的源码补全和名称请求。缺少必要交易数据仍然失败。
- 调试阶段优先复用已有合约名称；缺失名称查询限时，外部请求失败保留原地址与真实执行轨迹，记录警告。取消操作继续传播。
- 区块浏览器的 HTTP 200 错误响应不再作为合约数据写入缓存。
- 工作流记录失败阶段与异常类型，通过结构化日志和任务错误向用户展示；错误摘要不含服务密钥、响应正文或服务器路径。保留脱敏的详细文件日志。
- 未完成或没有有效报告时，前后端均返回“无法评估”，不显示风险评分。前端也防护旧后端仍返回默认分数的情况。
- 终态任务中没有输出的智能体显示“未执行”，不再一直显示“等待中”。

- 隔离副本后端测试 254 项、30 个子测试通过；10 条现有依赖/生命周期弃用警告。
- 使用实际 React 组件及产品样式进行浏览器验证：1440×900、768×1024、390×844，无横向溢出或 JS 错误；确认错误原因可见、失败任务无风险评分、未运行智能体无等待状态。
- Etherscan 域名只读连通测试 HTTP 200；一次已配置源码 API 的只读请求返回有效合约源码。目前可用不代表任务运行时没有发生超时，也不能证明完整链路已经恢复。
